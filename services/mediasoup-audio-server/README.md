# VibeMatch mediasoup Audio SFU POC

Standalone WebRTC audio SFU service for testing VibeMatch audio rooms without touching the current Flutter Live Room or FastAPI backend.

## Scope

- Audio-only WebRTC using mediasoup.
- SFU architecture, not peer-to-peer mesh.
- 17 speaker seats per room.
- Audience users can join and consume audio without publishing.
- Seated users can publish mic audio.
- Local self-mute and admin-mute state are represented in room state.
- Local coturn config is included for open-source TURN/STUN testing.
- Designed as a standalone module that can later move to a cloud server.

## Folder

```txt
services/mediasoup-audio-server
```

## Requirements

- Node.js 22 or newer.
- npm.
- Docker only if running local coturn.

## Run locally

```bash
cd services/mediasoup-audio-server
copy .env.example .env
npm install
npm run dev
```

Health check:

```bash
curl http://127.0.0.1:4000/health
```

Expected response:

```json
{
  "ok": true,
  "service": "vibematch-mediasoup-audio-server",
  "mode": "standalone-poc",
  "maxSpeakersPerRoom": 17
}
```

## Phone testing on same Wi-Fi

Set `ANNOUNCED_IP` and `TURN_HOST` in `.env` to your laptop Wi-Fi IP.

Example:

```env
ANNOUNCED_IP=192.168.1.8
TURN_HOST=192.168.1.8
```

Then restart the server.

## Run local coturn

```bash
docker compose -f docker-compose.turn.yml up -d
```

For production, replace static local TURN credentials with short-lived credentials generated by the main backend.

## Socket events

### joinRoom

Client sends:

```json
{
  "roomId": "test-room",
  "peerId": "6418123456"
}
```

Server returns router RTP capabilities, ICE servers, seats, and existing producers.

### takeSeat

A user must take one of the 17 seats before producing audio.

```json
{
  "roomId": "test-room",
  "peerId": "6418123456",
  "seatNo": 1
}
```

### createWebRtcTransport

Use direction `send` only for seated users. Use direction `recv` for listeners.

```json
{
  "roomId": "test-room",
  "peerId": "6418123456",
  "direction": "send"
}
```

### connectTransport

Connects the client-side DTLS transport.

### produce

Publishes audio to the SFU. Only seated users can produce.

### consume

Consumes another seated user's producer.

### setSelfMuted

Updates self-mute state.

### setAdminMuted

POC-level admin mute event. Later this must be authorized by FastAPI role and room permissions.

## Performance and cost notes

- mediasoup and coturn are open-source.
- This module avoids paid RTC services for testing.
- SFU avoids the heavy peer-to-peer mesh problem.
- Only 17 users can publish audio per room.
- Receive transports should be reused by clients.
- Audio is Opus-only.
- No recording, transcription, video, or paid services are included.
