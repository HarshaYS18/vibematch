# Provider-neutral infrastructure contract

No cloud provider is selected in this repository. This Terraform root validates the infrastructure bindings and PostgreSQL connection budget without creating fictional cloud resources. It accepts network, cluster, managed service, DNS/certificate, workload identity, secret manager, observability, and separate node-pool interfaces that a provider implementation must supply. `terraform_data` preconditions reject a single-zone production target or an overcommitted database pool budget.

Copy `terraform.tfvars.example` outside the repository and replace every placeholder with real provider outputs. Do not commit the completed file or credentials. Run `terraform fmt -check -recursive`, `terraform init -backend=false`, and `terraform validate` here. A real provider module should provision private networking, managed PostgreSQL with PITR, highly available single-primary Redis/Valkey for Lua media registry operations, durable JetStream, private S3-compatible storage with versioning, CDN, DNS/TLS, secret manager, workload identity, observability, and Kubernetes/node autoscaler pools. Provider selection, account IDs, domains, and access permissions are external prerequisites.

The sample budget is 30 API pods × 5 connections + 20 Inbox pods × 5 + 20 Vibes pods × 5 + 20 workers × 3 + 60 reserve = 470 connections within a 500 connection database limit. Replace these with measured and configured values; the sample is an invariant demonstration, not a capacity claim. Production deployment must also account for connection pooler mode, read replicas, failover headroom, and migration/admin sessions.
