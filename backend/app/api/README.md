# Canonical API layout\n\napp.api.router is the only production composition root. Route imports must not register child routers as side effects.\n\nCategories: system/identity, social/content, rooms/realtime, inbox/communication, economy/gifts/games/store, and administration.\n\nRules:\n\n1. A method + path pair is registered exactly once.\n2. Extend the canonical resource instead of creating parallel v2, mvp, compat, public, or placeholder APIs.\n3. Compatibility belongs in services/adapters, not in a second public route.\n4. SQLAlchemy state comes from app.database; Redis config comes from app.core.config.settings.redis_url.\n5. Production registration is explicit in app.api.router.\n
