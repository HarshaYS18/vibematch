# External prerequisites for production

Repository code and manifests can be reviewed without cloud credentials. Production deployment still needs an owner to select and provision the services below. Use a secret manager or workload identity; do not commit real values to `.env.example`, Kubernetes ConfigMaps, or Terraform state. The exact configuration names listed are the current application interfaces or manifest fields; provider-specific credential wiring must be reviewed for the selected cloud.

| Requirement | Why and exact interface | Verification | Repository work already present |
| --- | --- | --- | --- |
| Cloud account, region, cluster, registry | Kubernetes credentials, image registry access, node quotas and zone capacity; environment overlays in `deploy/kubernetes/overlays/{staging,production}` and image digests in workload manifests | `kubectl` reaches the correct context, images pull by digest, pod/node autoscaling can create a node under quota | Kubernetes base/overlays and workload definitions are being added; no live cluster is assumed |
| DNS and TLS certificate ownership | API and WebSocket hosts in `deploy/kubernetes/base/ingress.yaml`; public media `MEDIA_PUBLIC_URL`; allowed origins `CORS_ALLOWED_ORIGINS`, `REALTIME_ORIGINS`, `CORS_ORIGIN` | DNS resolves to edge; HTTPS/WSS certificate validates; origin and upgrade tests pass | API and realtime ingress definitions, media discovery contract |
| PostgreSQL with backup/PITR | `database_url` must target the PgBouncer transaction endpoint for application traffic; `MIGRATION_DATABASE_URL` targets PostgreSQL directly; provision `funkey-pgbouncer-auth`, dedicated `funkey-postgres-monitoring` credentials, `pg_stat_statements`, role/database timeout defaults, backups/PITR, and environment-specific connection limits | Restore a staging clone to a known point, run `alembic current`, render/smoke PgBouncer, verify pg_stat_statements/exporter metrics, deadlock/lock/long-transaction alerts, and validate client/server connection-budget arithmetic | Chunk 18 PgBouncer/exporter manifests, direct migration DSN, bounded SQLAlchemy pools, timeout/budget validation, local pg_stat_statements bootstrap, ownership audit SQL, saturation runbook |
| Three HA Redis/Valkey roles | Provision distinct production endpoints for `CACHE_REDIS_URL`, `REALTIME_REDIS_URL`, and `MEDIA_REGISTRY_REDIS_URL`; keep URLs in workload secrets, provide `funkey-redis-monitoring` exporter credentials, configure role-specific memory ceilings/eviction policies, TLS/private networking and failover. Current clients are single-endpoint clients; do not enable Redis Cluster. Media registry remains dedicated single-primary HA. | Run one-role-at-a-time failover drills, verify exporter/alerts, cache rebuild, rate-limit fail-closed behavior, realtime reconnect/snapshot resync, media heartbeat/re-resolution, and no durable-state loss | Chunk 19 role-specific clients, local three-Redis topology, machine contract, monitoring exporters, alerts, tests, ADR-015 and outage runbook; managed HA services remain external |
| Managed OpenSearch (production) | Private/multi-AZ OpenSearch with TLS, least-privilege credentials, snapshots, storage/heap/cluster-health monitoring; configure `OPENSEARCH_URL` and `SEARCH_INDEX_PREFIX` | Build/replay a versioned index, validate alias cutover, query p95 and node failure without business-state impact | Chunk 38 Search service, projection consumer, local/staging OpenSearch fixtures, tests/guard/runbook |
| Managed Kafka (production) | Multi-AZ Kafka with private networking, TLS/SASL, ACL identities for the bridge/consumers, broker storage/ISR monitoring; configure `KAFKA_BOOTSTRAP_SERVERS`, `KAFKA_SECURITY_PROTOCOL=SASL_SSL`, `KAFKA_SASL_MECHANISM`, `funkey-kafka-secrets` keys `kafka_username` and `kafka_password` | Provision topics from the canonical catalogue, verify bridge publish/consume, consumer lag, broker failover, bounded replay and ACL denial tests | Chunk 37 bridge, schemas/topic catalogue, local KRaft, staging KRaft integration cluster, CI smoke, replay and runbook |
| NATS JetStream | `NATS_URL`; KEDA NATS monitoring endpoint and stream/consumer names in autoscaling manifests | Broker health, stream and durable consumer exist, publish/consume/replay and lag metrics work | Local Compose NATS and event/worker foundation are being added |
| Object bucket and CDN | `MEDIA_STORAGE_DRIVER=s3`, `MEDIA_S3_BUCKET`, `MEDIA_S3_REGION`, `MEDIA_S3_ENDPOINT_URL`, access keys or workload identity, `MEDIA_CDN_BASE_URL`, `GIFT_CDN_BASE_URL` | Upload, retrieve, moderate, delete, and outage test with public/private ACL policy | Existing S3-compatible media storage abstraction and upload routes |
| Production secret manager | `JWT_SECRET_KEY`, `MEDIA_INTERNAL_TOKEN`, DB/Redis/NATS secrets, storage credentials, `INBOX_BACKUP_ENCRYPTION_KEY` and optional provider secrets | Pod receives secrets without values in Git or process arguments; rotation drill; unsafe defaults rejected | Environment templates and production configuration validation are being hardened |
| TURN and media network | TURN realm/secret/certificates, SFU `MEDIASOUP_ANNOUNCED_IP`, `MEDIASOUP_MIN_PORT`, `MEDIASOUP_MAX_PORT`, `MEDIA_PUBLIC_URL` | Real device call on direct and TURN-only networks; packet loss and relay bandwidth observed | `infra/turn/` and canonical SFU container/configuration |
| Monitoring and alert destinations | Prometheus/OpenTelemetry collection, logs, dashboards, paging route; metrics adapter for HPA custom metrics | `/live`, `/ready`, `/metrics` are scraped where implemented; test alert reaches on-call | Health endpoints and Kubernetes autoscaling/metrics contracts are being added |
| GitOps controller and deployment identities | Argo CD installation, repository access, environment promotion permissions, immutable image registry | Argo CD syncs a staging digest, reports drift, and rolls back compatible image/config | GitOps strategy ADR and reviewed deployment manifests; real controller is external |
| Optional identity and notification providers | `GOOGLE_AUTH_CLIENT_IDS`, `FCM_PROJECT_ID`, `FIREBASE_SERVICE_ACCOUNT_PATH`, Google Drive backup OAuth variables, optional SMS/email provider variables when added | Sign-in and push test in staging with restricted test accounts; provider failure handled | Existing auth, push, and backup integration surfaces |

Before production traffic, replace placeholder hosts and credentials, confirm network policy and firewall ports, run migration and restore drills, validate rollout/drain under load, and record the measured capacity of the actual environment. If a provider is not selected, keep that row open in the release checklist; do not claim it is deployed.
